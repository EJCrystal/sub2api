# EJ fork 版本规则

版本号以 `backend/cmd/server/VERSION` 为准。合并上游代码不会自动更新 fork 的发布编号，必须在发布前按以下规则修改；否则旧标签及发布后的版本回写会让源码和部署继续显示旧版本。

- 同步新的上游基础版本后，首次发布使用 `X.Y.Z-ej`，例如 `0.2.6-ej`。
- 基础版本必须与实际已同步的上游版本一致，以真实标签、VERSION 和提交为依据，不根据合并提交的标题推断版本，也不提前使用尚未发布的上游版本号。
- 上游基础版本不变，fork 后续修改依次发布为 `X.Y.Z-ej-1`、`X.Y.Z-ej-2`。修订号使用连字符，不使用 `.1`。
- 从旧的点号修订格式迁移时，延续修订计数，例如 `0.2.5-ej.6` 的下一次发布为 `0.2.5-ej-7`。
- 发布前先修改并提交 `backend/cmd/server/VERSION`，再在该提交创建完全匹配的 `v` 前缀标签，例如 `v0.2.6-ej`。
- Release 流程校验 fork 标签格式及其与 VERSION 的一致性；前后端均从指定标签构建。fork 发布结束后不再把标签版本写回主分支，避免旧发布覆盖新版本。
- 部署使用明确版本的镜像，并核对容器内 `sub2api -version` 和 `/health`。
